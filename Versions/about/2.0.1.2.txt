<h5>Changes since 2.0.1.0</h5>
<p>
Full update list: <a target="_blank" href="https://github.com/Madpeterz/StreamAdmin/issues/152">issue 152</a>
</p>
</div>
<div class="col-sm-12">
<h6>Before you upgrade</h6>
<ul>
<li>StreamAdmin now requires <strong>PHP 8.4</strong>. The docker image is built on php84; classic installs must upgrade PHP first.</li>
<li>Run <strong>Versions/2.0.1.1.sql</strong> to bring the database to 2.0.1.2 (new limit, coupon, credit, server and transaction fields).</li>
<li>If you ran a <strong>dev build from after May 2025</strong>, use the <strong>Reissue</strong> button on the System config page to replace your link codes and HTTP inbound secret. Those builds could reveal them in API error replies.</li>
</ul>
</div>
<div class="col-sm-12">
<h6>New features</h6>
<ul>
<li><strong>Marketplace coupons and credits</strong> (issue 127): sell credit packs on the SL marketplace. Credits can be used to buy or renew streams at system owner vendors.</li>
<li><strong>Rental limits</strong> (issue 131): limit how many streams each avatar can rent, overall and per package, and refuse renewals once a rental already has the maximum days remaining.</li>
<li><strong>Server IP</strong> (issue 138): set an IP on each server and use the new <code>[[SERVER_IP]]</code> swap tag in notecards.</li>
<li><strong>Server capacity</strong>: record bandwidth and storage per server, and see estimated usage on the servers page.</li>
<li><strong>Avatar last seen</strong> (issue 128): the system now tracks when an avatar last interacted, the first step towards automatic avatar cleanup.</li>
<li><strong>Bot web UI</strong> (issue 121): shortcuts to the bot UI and wiki on the bot page.</li>
<li><strong>Texture faces</strong> (issue 132): choose which faces textures render on as part of the vendor baked config.</li>
<li><strong>Config cleanup</strong> (issue 136): config files are deleted once config-less scripts have been set up.</li>
<li><strong>Stock level API</strong> (issue 151, experimental): an endpoint that reports available streams per server and package, for in-world availability displays.</li>
</ul>
</div>
<div class="col-sm-12">
<h6>Fixes</h6>
<ul>
<li>Bulk remove page did not load (issue 141).</li>
<li>User HUD was not updated (issue 140).</li>
<li>Removing an avatar with transactions gave an SQL error; their transactions are now reassigned to the system owner (issue 148).</li>
<li>Setting an avatar's credits to zero did not save.</li>
<li>Payment key updates give clearer errors when a key fails its checks.</li>
<li>Details resend and renew requests without a rental are rejected with a clear message.</li>
<li>Marketplace (ANS) notification handling reworked.</li>
<li>Bot notecard sync and command queue processing improved.</li>
<li>Cron tasks were rejected as "wrong grid connected" on recent dev builds.</li>
<li>Turning off the HUD Discord or group link no longer stores a NULL value; the update SQL also repairs existing rows.</li>
</ul>
</div>
<div class="col-sm-12">
<h6>Security</h6>
<ul>
<li>API signature errors no longer include the link code or inbound secret in the reply.</li>
<li>PhpSpreadsheet updated to 1.30.7, fixing several published vulnerabilities including two rated critical.</li>
</ul>
</div>
<div class="col-sm-12">
<h6>Platform and hosting</h6>
<ul>
<li>Upgraded to PHP 8.4, YAPF Bootstrap 6.3 and YAPF Framework 9.2; database models regenerated.</li>
<li>Fixed PHP 8.4 deprecation messages appearing in pages and API replies.</li>
<li>New <code>docker-compose.cloudflared.yml</code> for running behind a Cloudflare Tunnel, with settings and secrets read from a <code>.env</code> file.</li>
<li>Automated test coverage raised from 32.75% to 61.27%.</li>
</ul>
</div>
